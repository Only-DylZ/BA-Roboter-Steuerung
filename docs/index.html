IP-Adressen

Alle Geräte hängen über LAN-Kabel am selben Switch im Subnetz 192.168.3.x. Antippen kopiert die Adresse.

GerätIP-AdressePortWofür
Asyril EYE+ Controller7171EYE+ Studio (Browser), Bauteilkoordinaten
igus ReBeL (Steuerung im Sockel)3920iRC, Bewegungsbefehle
iRC-Simulation (lokal)3921nur Modus „Simulation“
Eigener PC192.168.3.x–x = freie Zahl 2–254, nicht 11 oder 20 (bisher: 30)

Subnetzmaske am PC: 255.255.255.0 · Gateway und DNS leer lassen.

Der EYE+ Controller hat ab Werk die Adresse 192.168.1.50. Falls er zurückgesetzt wurde, ist er nur dort erreichbar – dann den PC vorübergehend auf 192.168.1.x stellen.

Anlage einschalten

  1. Schaltkasten ansteckenStecker des Schaltkastens in die dreiphasige Starkstromsteckdose (400 V) im Labor stecken.
  2. Hauptschalter einschaltenDen Hauptschalter außen am Schaltkasten auf ON drehen. Danach leuchten die Asyril-Komponenten (EYE+ Controller, Asycube, Asyfill). Der Controller braucht etwa eine Minute zum Hochfahren.
  3. Switch einschaltenNetzteil des Netzwerk-Switches einstecken. Controller und Roboter müssen per LAN-Kabel am Switch hängen.
  4. igus ReBeL an Strom ansteckenNetzteil des Roboters in die Steckdose stecken.
  5. On-Knopf am Sockel drückenDer Knopf sitzt am Sockel des ReBeL. Not-Aus muss entriegelt sein.
  6. PC mit dem Switch verbindenLAN-Kabel vom PC in einen freien Port des Switches stecken und die IP wie unten einstellen.

PC einrichten (feste IP)

Ohne feste IP im Subnetz 192.168.3.x erreicht der PC weder Roboter noch Controller.

  1. Netzwerkverbindungen öffnenWin + R → ncpa.cpl → Enter.
  2. Ethernet-Adapter wählenRechtsklick auf den LAN-Adapter → Eigenschaften → „Internetprotokoll, Version 4 (TCP/IPv4)“ → Eigenschaften.
  3. Adresse eintragen„Folgende IP-Adresse verwenden“: IP-Adresse 192.168.3.x, Subnetzmaske 255.255.255.0, Standardgateway leer → OK.
  4. Verbindung testenIn der Eingabeaufforderung (cmd):
ping 192.168.3.11
ping 192.168.3.20

Antwortet ein Gerät nicht, liegt es an Kabel, IP-Einstellung oder Stromversorgung – die Steuerungssoftware kann das nicht ausgleichen. Nach der Arbeit die IP am PC wieder auf „automatisch beziehen“ stellen, sonst funktioniert das normale Netz nicht.

EYE+ Studio (Kamera, Kalibrierung, Rezepte)

EYE+ Studio läuft direkt auf dem Controller, es muss nichts installiert werden.

  1. PC am Switch, IP eingestelltSiehe oben.
  2. Browser öffnenDie IP des Controllers in die Adresszeile eingeben: http://192.168.3.20
  3. StartseiteVon dort erreicht man Camera Configuration, Hand-Eye Calibration und Recent Recipes.

Wie viele Teile auf der Plattform liegen sollen und wie der Asycube rüttelt, steht im Rezept. Das lässt sich nur in EYE+ Studio ändern, nicht in der Steuerungssoftware.

iRC – Roboter direkt ansteuern

igus Robot Control (iRC) ist die kostenlose Herstellersoftware. Damit wird der Roboter von Hand verfahren, referenziert, Fehler quittiert und Positionen abgelesen (z. B. für die Hand-Auge-Kalibrierung). Außerdem enthält sie die Simulation, die der Modus „Simulation“ benötigt.

  1. iRC herunterladenÜber das Formular bei igus, kostenlos.
  2. Mit dem Roboter verbindenReBeL 6-DOF wählen und mit der Steuerung unter 192.168.3.11 verbinden.
  3. Roboter bereit machenFehler zurücksetzen (Reset), Motoren freigeben (Enable), Roboter referenzieren. Erst dann nimmt er Bewegungsbefehle an.

iRC darf beim Betrieb der Steuerungssoftware offen bleiben (empfohlen, wegen Fehlermeldungen im Klartext). Die Software holt sich beim Start automatisch die Kontrolle über den Roboter.

Steuerungssoftware von GitHub

Nur bedienen

Fertige PickAndPlace.exe aus dem aktuellen Release herunterladen und starten. Python wird nicht benötigt.

EXE herunterladen

Weiterentwickeln

Ganzes Repository herunterladen (Code → Download ZIP oder git clone). Benötigt Python 3.10+ unter Windows, keine Zusatzpakete.

Repository

Aus dem Quelltext starten

git clone https://github.com/Only-DylZ/BA-Roboter-Steuerung.git
cd BA-Roboter-Steuerung
python pick_and_place_gui_v2.py

Immer aus dem eigenen Ordner starten, sonst wird die Roboter-Bibliothek in libs/ nicht gefunden.

Neue EXE bauen

Die EXE ist eine eingefrorene Kopie des Codes. Skript geändert → EXE neu bauen, sonst läuft ohne Warnung der alte Stand.

  1. build_exe.bat doppelklickenPrüft Python, installiert bei Bedarf PyInstaller und baut die EXE (dauert einige Minuten).
  2. ErgebnisDie neue Datei liegt unter dist\PickAndPlace.exe.
  3. Optional veröffentlichenÄnderungen committen und die neue EXE als Release auf GitHub hochladen, damit der Download-Link oben aktuell bleibt.

Ausführliche Doku zu allen Parametern: README im Repository.

Betrieb

  1. Modus wählenSimulation (iRC-Simulation + simuliertes EYE+), Produktion (reale Hardware) oder Genauigkeitstest (realer Roboter ohne EYE+). Wer die Anlage nicht kennt, beginnt mit Simulation.
  2. Parameter prüfen„Standardwerte laden“ setzt die hinterlegten Werte, inklusive der IP-Adressen.
  3. START drückenDas Live-Terminal rechts zeigt jeden Schritt.

Vor dem ersten Produktionslauf

  • Roboter eingeschaltet, referenziert, keine Fehler in iRC
  • Not-Aus erreichbar und frei, Arbeitsbereich frei
  • Greifer angeschlossen, Bauteile auf dem Asycube
  • Beide Geräte per ping erreichbar
  • Geschwindigkeit (Override) beim ersten Lauf niedrig, z. B. 20 %

Ausschalten

  1. Ablauf stoppenIn der Steuerungssoftware stoppen und Programm schließen, Roboter in sichere Stellung fahren.
  2. Roboter ausAm Sockel ausschalten, Netzteil ausstecken.
  3. Schaltkasten ausHauptschalter außen am Schaltkasten auf OFF drehen, Stecker ziehen.
  4. Switch ausNetzteil ausstecken. Am PC die IP wieder auf automatisch stellen.

Wenn etwas nicht geht

Ping kommt nicht zurück

Kabel am Switch prüfen, IP und Subnetzmaske am PC prüfen, Gerät eingeschaltet? WLAN am PC testweise ausschalten.

EYE+ Studio lädt nicht

Controller ist noch nicht hochgefahren oder steht auf Werks-IP 192.168.1.50.

Doppelklick auf die EXE bewirkt nichts

Die EXE hat kein Konsolenfenster und zeigt Startfehler nicht an. Über Python starten (siehe oben), dann steht die Ursache im Klartext da.

„libs/CRI_Python_Lib konnte nicht geladen werden“

Aus dem falschen Ordner gestartet oder der Ordner libs fehlt.

Roboter fährt nicht

In iRC nachsehen: Fehler aktiv, nicht referenziert oder Not-Aus gedrückt.
